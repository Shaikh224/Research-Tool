The agent — what it does, where a human was needed

Deterministic by design

The agent extracts facts (auth, access model, API type, MCP). The verdict is computed by a transparent rule — not guessed — so it is reproducible and auditable. Raw scrapes are cached, so re-runs and the whole verification pass cost zero credits.

Where a human was needed
  • Obscure / thin-doc apps (iPayX, Paygent, fanbasis, Waterfall.io, higgsfield) where search returns little.
  • Not-an-API edge cases (Sherlock OSS CLI, Mermaid CLI) and name collisions.
  • The 20 gold labels that anchor the accuracy check — and spotting stale ones.

Limitations & honesty

Data completeness. Not every page states everything; the few apps that still read unknown are flagged, not guessed.

Stale gold labels. A few MCP disagreements (Salesforce, Slack, Twilio, Plaid) are likely the hand-labels being out of date, not agent errors — the agent found an MCP reference on the page. Refreshing these is part of the human loop.

Auth is the weakest field. A handful of JS-heavy docs landing pages returned no auth section; those show none and are honest gaps.

Name collisions. Generic names (e.g. "Sherlock") can resolve to the wrong product; flagged where spotted.

Composio coverage is reviewer-seeded for the zero-credit signal; set COMPOSIO_SEARCH=true to confirm exact toolkit URLs live.

No metric-gaming. Gold labels were never edited to match the agent; the number is what it is.
